# MyManabi コンセプト

MyManabi の目的・方針・前提・到達点・保留事項・リスクを記録する。具体的な学習フローやデータ仕様は [仕様（spec）](../spec/README.md) を参照。

このメモは完成仕様ではない。家庭内で使う PoC を作り、実際の利用から判断材料を得るための出発点である。

## 1. 目的

MyManabi は、子どもの家庭学習を支援するための AI 学習環境である。

単に正解を返すアプリではなく、次を重視する。

- 教科書に沿って学習を一度走り切れること
- 分からない箇所や判定への違和感を、その場で簡単に示せること
- AI が解決できない問題を無理に AI 内で完結させず、大人との会話へ渡せること
- 正答率だけでなく、到達水準、安定性、つまずき方を記録できること
- AI の教材生成、採点、説明がどこまで実用になるかを PoC で検証すること

学年は、学習順序を縛るための条件としては扱わない。学ぶ側にとって重要なのは、理解できる順序と関心である。必要なら教科書との対応を示す参考情報として保持する。

## 2. 初期 PoC の前提

- Windows PC 上で動く Rust + Tauri アプリとして実装する
- AI バックエンドは codex app-server（Rust 製、JSON-RPC over stdio）を子プロセスとして駆動する
- ChatGPT Plus の定額利用範囲で、家庭内利用がどこまで成立するか確認する
- 保存先は原則ローカルとする
- 利用者は一人または二人を想定する
- 学習者はアイコンで切り替え、内部データは学習者別フォルダに分ける
- 教材は Obsidian Vault で管理する
- 初期段階では一つの教科書、一つの単元から始める

子ども向けの画面は本アプリ（Rust + Tauri、フロントは React）が持つ。codex app-server は子ども向け UI ではなく、本アプリが JSON-RPC で駆動する AI バックエンド（問題生成・解説・非決定論的な採点）として使う。決定論的な採点・イベント記録・学習フロー制御は本アプリ側のコードが担う。初期 PoC では、定額枠を利用して教材生成、採点、補足説明、記録、レポート生成の流れが成立するかを検証する。

将来、Android 対応や独立アプリ化が必要になった場合は、OSS として別の実行基盤も検討する。現時点では Android を初期要件にしない。

## 3. 最初の到達点

初期 PoC では、次の一連の流れが家庭内で成立することを確認する。

1. アイコンで学習者を選ぶ
2. 教科書順で問題を出す
3. 回答、`分からない`、`納得できない` を記録する
4. AI が採点し、必要なら補足説明を最大 10 回まで出す
5. 学習終了時に日次レポートをローカル生成する
6. 大人が確認対象を見て、口頭で話し、結果を分類する
7. 未解決箇所を後で基礎から再学習する

教材は、実際に利用する教科書から一単元だけ選ぶ。基礎、標準、応用、最難関の類題、文章題などの探索問題を少数ずつ用意する。

候補として `分数のたし算` は扱いやすいが、実際に利用する子どもの教科書と学習状況を優先する。

## 4. 保留事項

現時点で決めない事項:

- 中断後の再開方法
- 通常学習へ基準問題を混ぜる際、本人へどこまで明示するか
- テスト対策の問題数、時間、年齢別の設計
- 日次レポートの詳細度
- メール添付や Google Drive など、外部共有の具体方式
- Android 対応や独立アプリ化
- 自由チャットから通常学習へ戻す詳細な導線
- 補足説明の適切な最大回数。PoC では最大 10 回として観測する

## 5. 批判的に確認すべき点

- 子ども向け UI は本アプリ（Tauri + React）で新規に作る。操作性、誤操作防止を検証する必要がある
- codex app-server は AI バックエンドであり、ChatGPT Plus 定額枠でのレイテンシ・利用上限・セッション安定性を検証する必要がある
- ChatGPT Plus の定額利用範囲で、家庭内 PoC が実用になるかは未検証である
- AI の生成問題、採点、解説は、もっともらしく誤る可能性がある
- 大人との口頭確認は教育的に重要だが、頻発すると家庭の負担になる
- 学習を一巡する方針は全体把握に向くが、前提不足を積み重ねる可能性もある
- `納得できない` や `分からない` が頻発する形式は、自動採点の対象として未成熟と判断すべきである
- 正答率だけでなく、安定性、問題数、難易度、本人の不安、異議を合わせて見る必要がある
